## 抽出一套标准玩法框架

一个 3D 战斗技能天然是几件事同时发生：某一帧播这段动画、某一帧开始判定、某一帧镜头推近、某一帧出特效、某一帧顿一下。每个技能都各写一遍"什么时候播动画、什么时候开判定、什么时候动相机"，重复实现的时序迟早会漏（判定开早了、镜头没复位），调一个数值要改代码重编译重打包，不同人写的技能风格也各不相同，后面接手的人读不懂。

我把这些能力集成成一套标准玩法框架：技能只描述"第几帧发生什么"，怎么发生由框架提供、由逻辑层决定。加一个技能是配一份数据，加一种表现才需要写一个类。

## 配置层与逻辑层分离

配置层是纯数据：`SkillClip` 里按帧索引的动画事件、自定义事件、相机事件、检测事件、音效事件、特效事件。它们全部是同一个基类下的派生类型，靠 Odin 的多态序列化直接存进资产：

```csharp
[NonSerialized, OdinSerialize]
public SkillAnimationData AnimationData = new();   // 派生类型由 Odin 自行还原
```

加一种新事件类型，不需要改序列化代码、不需要写自定义 SerializedObject，声明一个类挂上去就行。

逻辑层是可插拔的处理器：伤害结算、音效播放、特效生成、顿帧、震屏各自是一个 `Processor`，按 `typeof(T)` 注册进字典。播放器分发时查表，没注册就静默跳过。Demo 里玩家注册了 5 个处理器、敌人只注册 4 个，同一个技能在两种角色身上表现不同，但不需要改技能配置。

两层之间只有"事件类型"这一个契约，所以配置可以给任何人复用，逻辑可以随角色定制。

## 播放器：按帧展开的事件流

技能配置里的每一处数据，都是一个会在某一帧触发的事件。播放器每帧要做的，就是触发所有可能在这一帧触发的事件，把对象在该帧的状态复现出来。所以 `Skill_Player` 的职责是按帧把配置展开成调度序列：

```
每帧：
  targetFrame = 累计时间 × 帧率          // 时间驱动，不是帧计数
  while (当前帧 < targetFrame) {
      触发 自定义事件
      触发 动画事件
      触发 音效事件
      触发 特效事件
      触发 检测事件
      触发 相机事件
      当前帧++
  }
```

时间是连续的，掉帧时要把漏掉的帧补上，所以一次 `Update` 可能连续推进多个逻辑帧。帧内顺序固定，因为"先改状态、再播表现、最后判定"之间存在依赖。新增一种事件只要加一个数据类加一段分发，它本来就只是事件流里的一种。

## 相机轨道

镜头是 3D 战斗的一半手感，所以相机也被做成轨道，和动画、检测平级。一条相机轨道上可以摆多种相机事件：

| 事件 | 行为 |
| --- | --- |
| `CameraFovChangeEvent` | 按曲线插值 FOV，结束后复位原值 |
| `CameraRotateEvent` | 相对宿主朝向做旋转 Slerp，结束复位 |
| `CameraImpulseEvent` | 通过 Cinemachine 施加震屏 |
| `CameraResetEvent` | 复位所有处理器并关闭技能相机 |

每个事件配一个 `CameraEventProcessor`，它有四段生命周期：`StartEvent` / `TickEvent` / `EndEvent` / `ResetProcessor`。"镜头推近再拉回"这种效果因此天然有始有终，技能被打断后镜头也不会卡在半路。

和检测事件的区别在时间轴口径：相机事件走秒制（按持续时间推进），检测事件走帧制。镜头运动本来就是连续的，用帧数描述反而不自然。

技能相机本身由 `SkillCamera` 管理：进入技能时抬高优先级并接管跟随，技能结束后还原姿态和优先级，不和普通跟随相机打架。

## 读图要点

1. 没有"前摇/判定/后摇"的阶段枚举。阶段由帧位置加轨道事件表达，不同技能节奏差异太大，写死阶段反而限制表现。
2. 帧内分发顺序固定：自定义 → 动画 → 音频 → 特效 → 攻击检测。行为节点可以在 `Before/After` 钩子里改写或吞掉事件。
3. 表现层是纯扩展点：处理器按 `typeof(T)` 注册，加一种命中表现不用改播放器。
4. 检测有两条路：武器 `SkillChecker` 的 trigger 探测，和 `SkillAttackDetectionTool` 的盒/球/扇 `OverlapNonAlloc` 扫描。前者适合持续判定，后者适合瞬发范围。

## 核心类型

| 类型 | 职责 |
| --- | --- |
| `Skill_Player` | 技能播放器：帧推进、事件分发、处理器注册表 |
| `SkillClip` | 一个技能片段：帧数、帧率、六大数据容器 |
| `SkillBehaviourBase` | 技能的逻辑节点，可深拷贝成原型 |
| `SkillBrainBase` | 技能决策与生命周期、行为字典、共享数据总线 |
| `AttackDetectionEvent` | 检测事件：形状、角度、距离、触发的后续事件 |
| `CameraEventBase` | 相机事件基类，配四段生命周期的处理器 |
| `SkillCamera` | 技能相机：优先级、跟随、姿态保持与复位 |

## 扩展方式

- 加一种技能事件：写数据类（继承对应基类）和容器，挂到 `SkillClip` 上；在 `TickSkill` 里加一个分发分支；再写对应的处理器抽象。
- 加一种命中表现：继承 `DetectionEventProcessor`，在角色控制器里用 `RegisterDetectionEventProcessor` 注册一行。
- 加一种镜头运动：继承 `CameraEventBase` 和 `CameraEventProcessor`，用 `[CameraEvent]` 标注，编辑器的加号菜单会自动出现。
