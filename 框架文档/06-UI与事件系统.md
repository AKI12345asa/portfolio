# 06 UI 系统与事件系统

## 一句话定位

UI 系统是「特性声明 + 反射建表 + 按层挂载」的窗口管理器：`UIWindowDataAttribute` 一行写清 key、层级、资源地址、是否缓存、是否预初始化，`UISystem` 负责实例化、缓存、显隐与层级遮罩。事件系统是两套平行实现——全局的「字符串 key + `Action` 泛型多播」事件中心（`EventSystem` / `EventModule`），与组件级「int 键转发器」`EventListener`（配 `FrameEventExtend`）。框架层两者无绑定，耦合发生在业务层：窗口在 `Init()` 订阅全局事件，逻辑层 `EventTrigger` 派发。

## 运行流程

### UI

1. `MyFrameRoot.Awake`（`DefaultExecutionOrder(-20)`）→ `InitSystems()`，顺序为 Save → Pool → Event → **UI** → Mono → Audio → Time。
2. `UISystem.Init()` 用 `GetComponentInChildren<UISystem>()` 取实例，`InitInstance()` 重建 `_layouts = GetComponentsInChildren<UILayout>().ToList()`：**列表下标即 layer 号**。
3. 窗口表由 `MyFrameRoot.InitWindowDataInConfig()` 生成（运行时与编辑器 `TryInitFrameRootOnEditor` 都会走）：反射扫描全部程序集，把每个 `UIWindowDataAttribute` 转成 `UIWindowData`，`TryAdd` 进 `MyFrameSetting.UIWindowDataDic`。
4. `PreInitWindows()`：仅 `ifCache && ifPreInit` 的窗口被预实例化；`layerNum` 越界抛 `Exception`；创建后 `Init()` → `SetActive(false)` → 挂到 `layout` 末尾 → `layout.OnWindowShow()` → 入 `WindowCacheDic`。
5. `ShowWindow(key | Type | T, layer = -1)`：查表，未注册抛异常；`layer == -1` 时取 `windowData.layerNum`，越界抛异常。
6. 命中缓存且 `UIEnabled` → 对旧层 `OnWindowClose()`；未命中 → `ResSystem.InstantiateGameObject<UIWindowBase>(assetPath, layout.root, objName: key)` + `Init()`。
7. 统一收尾：`SetActive(true)` → `SetParent(layout.transform)` → `SetAsLastSibling()` → `ShowGeneralLogic(layer)`（写 `currentLayer`、调 `OnShow()`、置 `uiEnabled = true`）→ `layout.OnWindowShow()`。
8. `Close(key)`：`CloseGeneralLogic()`（`OnClose()` → 隐藏 → `uiEnabled = false`）→ `layout.OnWindowClose()`；`ifCache` 为真则留在缓存，否则 `ResSystem.UnloadInstance()` 并从 `WindowCacheDic` 移除。

### 事件

1. `EventSystem.Init()` → `eventModule = new EventModule()`；`EventModule` 的 `objectPoolModule` 是 `static`，跨实例共享。
2. 订阅：`EventSystem.AddEventListener(name, action)` → `EventModule` 查 `eventInfoDic`，已存在则 `Delegate.Combine` 叠加多播，否则从池取条目并 `Add`。
3. 派发：`EventTrigger(name, args…)` → `TryGetValue` → 强转为 `MultipleParameterEventInfo<Action<…>>` → `action?.Invoke(...)`；key 不存在静默返回。
4. 退订：`RemoveEventListener` 只做 `Delegate.Remove`（key 保留，`action` 可能变 null）；`RemoveEvent(key)` 才删键并 `Destory()` 回池；`Clear()` 清表回池。
5. 组件级：`com.OnClick(action)` → `GetOrAddEventListener`（无则 `AddComponent`）→ 按 `(int)EventType` 存 `EventListenerEventInfos<T>`，内部 `List<IEventListenerEventInfo<T>>` 保序。
6. Unity 回调进 `EventListener.OnPointerClick` 等 → `TriggerAction<T>(EventType.OnClick, eventData)` → 顺序遍历 `action(eventData, arg)`。
7. `EventListener.OnDestroy` 先派发 `OnReleaseAddressableAsset`、`OnDestroy`，再 `RemoveAllListener()` 把容器与条目全部回池。

## 关键机制详解

### UI 一：窗口注册——特性即注册表

`UIWindowDataAttribute(windowKey, ifCache, assetPath, layerNum, ifPreInit)` 声明在窗口类上；`Type` 版本直接把 `type.FullName` 当 key，代价是 `ShowWindow<T>` / `Close<T>` 找不到它（那两处用的是类型名 `typeof(T).Name` / `windowType.Name`，见 `UISystem.cs` 第 84、126 行）。建表用 `FrameUtility.GetTypesByBaseTypeAndAttribute<UIWindowBase, UIWindowDataAttribute>`，条件是 `baseType.IsAssignableFrom(type.BaseType)`，即类必须（间接）继承 `UIWindowBase`；结果 `TryAdd` 去重后写进 `MyFrameSetting` 这个 ScriptableObject，所以窗口表是**资产里持久化 + 每次启动重建**的。表本身在 `MyFrameRoot.WindowDataDic` 里惰性创建，但缺 `setting` 时返回 `null`，此时 `ShowWindow` 直接 `TryGetValue` 会 NRE。

### UI 二：层级与遮罩——`UILayout` 与 sibling index

`LayoutPrefab.prefab` = `Canvas` + `GraphicRaycaster` + `UILayout`，其中 `root` 序列化指向**它自身的 RectTransform**，`Mask` 是它的子物体 Image。`UILayout.Update()` 只做一件事：把 `maskImage` 的 sibling index 设为 `root.childCount - 2`。因为窗口 `SetParent` 后总是 `SetAsLastSibling`，所以遮罩恰好压在「最新的那个窗口」之下、其余窗口之上——顶层窗口不被遮罩挡住，更早的窗口被遮罩拦截射线。子物体不足 2 个时置 0。`count` 字段只自增自减，**从未参与计算**（`Reset()` 也没有调用点），属残留。`UILayoutData`（遮罩 sprite/颜色/开关/射线拦截）只在编辑器点「刷新UI层」（`FrameWindow` → `UISystem.RefreshUISystem`）时经 `UILayout.Init` 烘焙进场景里的 Layout 实例，运行时不再读 `UILayoutDataList`。

### UI 三：缓存、预初始化与资源归属

打开窗口的实例化链路是 `ResSystem.InstantiateGameObject`：先拿 `assetPath` **当池名**查 GameObject 池（池不存在则返回 null），未命中才 `Addressables.InstantiateAsync(...).WaitForCompletion()`；`autoRelease` 默认为 true，会注册 `OnReleaseAddressableAsset(AutomaticReleaseAssetAction)`，即对象销毁时自动 `Addressables.ReleaseInstance`。关闭时若 `ifCache == false`，还会显式 `ResSystem.UnloadInstance(gameObject)`——同一次销毁上既有自动释放又有显式释放，⚠ 待确认是否重复 Release（需看运行日志）。`ifCache == true` 的窗口只隐藏，实例句柄持有到进程退出；两种路径都**不回 GC 对象池**，所以「按 assetPath 查池」这条分支只有在有人预先建过同名池时才会命中。

### 事件一：数据结构与泛型约束（最容易想当然的地方）

表是 `Dictionary<string, IEventInfo>`，`IEventInfo` 只有 `void Destory()`。无参事件用 `EventInfo { Action action }`；有参事件用 `MultipleParameterEventInfo<TAction> where TAction : MulticastDelegate`，字段就是 `TAction action`——**一个 key 一条多播委托**。加入与触发两端都要把条目强转成 `MultipleParameterEventInfo<Action<具体类型…>>`，因此同一 key 的订阅签名与派发签名必须完全一致：写错类型不编译报错，而是运行期 `InvalidCastException`；把无参 key 当有参派发同样会抛异常。另有两处复制粘贴遗留：`EventModule` 9 参 `EventTrigger` 写成 `.action.Invoke`（缺 `?.`，第 160 行），key 尚在而监听已清空时 NRE；`EventSystem` 13 参 `AddEventListener` 末位类型参数写成 `T2`（应为 `T12`，第 109 行）。

### 事件二：无 GC 取向与缺失的能力

`EventModule` 用 0~16 共 17 个定长重载替代 `params object[]`，注释直言「避免使用 params 产生数组 GC、装箱问题」：泛型 `T` 直接作形参，struct 事件参数不装箱。条目对象走 `ObjectPoolModule`（按 `GetType().FullName` 分池），`Destory()` 清引用后入池；但池为空时 `ObjectPoolData.GetObject` 走反射构造（`_constructorInfo.Invoke`），首次与池空反而比 `new` 慢。**没有优先级、没有取消/拦截、没有线程安全**——普通 `Dictionary` 无锁，只能主线程调用；回调里增删同一 key 的监听即直接改多播链，行为不受保护。

### 事件三：`EventListener`——另一套平行的组件级转发器

它的键是 `int`（`EventType` 负值枚举 + 自定义 int），与 `EventSystem` 的字符串表毫无关系。由 `FrameEventExtend` 的 `Component` 扩展按需 `AddComponent` 挂载，实现 8 个 UGUI 指针接口并手写 `OnCollision*`/`OnTrigger*`；每类事件存 `EventListenerEventInfos<T>`（内含保序 `List`），条目两种形态：`Action<T>` 与 `Action<T, TEventArg>`（把固定参数 `args` 存进条目，省掉闭包）。`RemoveListener` 只比较 `action.Equals`、**不比较 `args`**，与注释「同一个函数+参数」不符。`OnDestroy` 自动清空回池，组件销毁无需手工退订；`TriggerAction` 里 `(infos as EventListenerEventInfos<T>)` 类型不符时是 NRE 而非可读报错。`ResSystem` 的自动释放正挂在这个 `OnDestroy` 上。

## 对外 API 与扩展点

### 加一个 UI 窗口

```csharp
// 参数顺序：windowKey / ifCache / assetPath / layerNum / ifPreInit
// assetPath 同时是 Addressables 地址与 GameObject 池名
[UIWindowData(nameof(ShopWindow), true, nameof(ShopWindow), 2, true)]
public class ShopWindow : UIWindowBase
{
    public override void Init()   // 创建或预创建后调用一次
    {
        EventSystem.AddEventListener<int>("OnGoldChanged", RefreshGold);
    }
    public override void OnShow() { /* 每次显示 */ }
    public override void OnClose() { /* 每次隐藏/关闭 */ }

    private void RefreshGold(int gold) { /* ... */ }
}

UISystem.ShowWindow<ShopWindow>();     // 打开（可用第二参数临时指定层）
UISystem.GetWindow<ShopWindow>();      // 取（未创建返回 null）
UISystem.Close<ShopWindow>();          // 关闭
```

`ifCache == false` 的窗口关闭即销毁，`Init` 里订阅的全局事件必须在 `OnClose`/`OnDestroy` 中 `EventSystem.RemoveEventListener` 退订，否则委托会一直抓着已销毁的组件。

### 定义并派发一个事件

```csharp
// 1) 定义：约定 key 常量即可（没有类型化的事件类）
public static class EventKeys { public const string OnGoldChanged = "OnGoldChanged"; }

// 2) 订阅
EventSystem.AddEventListener(EventKeys.OnGoldChanged, OnGoldNoArg);        // 无参 Action
EventSystem.AddEventListener<int>(EventKeys.OnGoldChanged, RefreshGold);   // 1 参
EventSystem.AddEventListener<float, float>("UpdateHp", OnHpChanged);       // 2 参

// 3) 派发：参数类型必须与订阅时完全一致
EventSystem.EventTrigger(EventKeys.OnGoldChanged, 100);
EventSystem.EventTrigger("UpdateHp", 35f, 100f);

// 4) 退订
EventSystem.RemoveEventListener(EventKeys.OnGoldChanged, RefreshGold);
```

### 组件级事件（`EventListener` + `FrameEventExtend`）

```csharp
this.OnClick(() => Debug.Log("click"));                                   // 自动挂 EventListener
this.OnCollisionEnter((Collision c) => Debug.Log(c.gameObject.name));
this.OnClick((PointerEventData e, int id) => Debug.Log(id), args: 3);     // 带固定参数
this.AddEventListener<GameObject>(90001, go => { /* 自定义 int 键 */ });
this.TriggerCustomEvent(90001, gameObject);
this.RemoveAllListener();                                                 // 组件销毁时也会自动清
```

## 与其他模块的耦合

- **`MyFrameRoot`**：初始化顺序决定可用性（Event 早于 UI）；窗口表与层配置取自 `MyFrameSetting` 资产；编辑器 `TryInitFrameRootOnEditor` 先 `InitSetting()` 再 `InitSystems()`，故非运行态也能建表。
- **`ResSystem` + Addressables**：UI 只经 `InstantiateGameObject` / `UnloadInstance` 创建释放，`assetPath` 即 Addressables 地址；反向地，`ResSystem` 用 `FrameEventExtend.OnReleaseAddressableAsset` 把 `EventListener.OnDestroy` 当自动释放钩子——这是事件系统在框架内**唯一**的实际使用者。
- **`PoolSystem`**：UI 打开时以 `assetPath` 为池名尝试复用 GameObject；`EventModule` 与 `EventListener` 各持独立 `ObjectPoolModule`（前者 static），互不共享。
- **`FrameUtility`**：靠 `AppDomain.CurrentDomain.GetAssemblies()` 全程序集反射建表，窗口类必须可被扫到且继承 `UIWindowBase`。
- **UI ↔ 事件**：框架层零绑定（`UISystem` 无一行事件代码）。耦合全在业务层：窗口在 `Init()` 订阅，`PlayerController` / `DemoEnemyController` 用 `EventSystem.EventTrigger("UpdatePlayerHp", …)` 派发，示例见 `Demo\Script\Player\UI\Demo_GameSceneWindow.cs`。
- **`AudioSystem` / `TimeSystem` / `MonoSystem`**：本次范围内未见与 UI、事件的调用关系。

## 设计亮点与可改进点

亮点：

- 特性即注册表：一个特性写清 key/层/路径/缓存/预初始化，`TryAdd` 去重，缺 setting 有告警兜底。
- `ifCache` 与 `ifPreInit` 正交，可表达「常驻后台」「启动预建」「用完即毁」。
- 事件层为 GC 做过设计：定长重载、泛型形参免装箱、条目池化，高频派发稳态零分配。
- `FrameEventExtend` 把组件级回调压成一行，`EventListener` 在 `OnDestroy` 自动回池解绑。
- 遮罩靠 sibling index 而非另开层级，一个 Image 就做到「挡下层、不挡顶层」。

可改进点：

1. `AddTypeEventListener<T>`/`TypeEventTrigger<T>` 用 `nameof(T)` 作 key。按 C# 规范，`nameof` 作用于类型参数返回的是参数名「T」而非实参类型名，所有类型事件会挤在同一 key 上。⚠ 待确认（未找到规避代码，正确写法应为 `typeof(T).Name`），确认前勿用。
2. 校验全靠强转：同 key 换签名只在运行期抛 `InvalidCastException`，建议加 `is` 判断给出可读报错，或改为以 `Type` 为键。
3. 复制粘贴遗留两处：`EventModule` 9 参 `EventTrigger` 缺 `?.`（第 160 行）；`EventSystem` 13 参重载末位写成 `T2`（第 109 行）。
4. `RemoveEventListener` 只清委托不删 key，会残留空条目；`WindowDataDic` 缺 `setting` 返回 null，`ShowWindow` 直接 NRE。
5. `UIWindowDataAttribute` 标了 `AllowMultiple = true`，但 `FrameUtility` 用 `GetCustomAttribute<T>()` 单取，按 .NET 语义多个同类特性会抛 `AmbiguousMatchException`（⚠ 待确认是否有意）。
6. `UILayout.count` 从未参与计算且 `Reset()` 无调用点；关闭窗口不回对象池，`assetPath` 当池名的分支实际很少命中。
