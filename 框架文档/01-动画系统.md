# 01 动画系统

## 一句话定位

一套绕过 Animator 状态机、直接用 Playable API 手搭动画子图的自研动画系统：`Animation_Controller` 持有 `PlayableGraph` 与双端口主 `AnimationMixerPlayable`，各类 `AnimationNodeBase` 节点把自己的 Playable 子图接到主混合器端口上，通过协程线性插值两个端口的权重完成过渡，通过外部参数实时改写各层 mixer 的输入权重完成混合。

> 说明：范围内实际为 **15 个 .cs**（主目录 11 + Config 4），非 16 个；含空行合计 4179 行（其中主目录非空行 3665 行）。

## 运行流程

1. **挂载与初始化**：控制器自身没有 `Awake`，由业务显式调用 `Init()`（Demo 中为 `DemoPlayerView.Init` / `DemoEnemyController`）。`Init` 依次 `PlayableGraph.Create` → `SetTimeUpdateMode(GameTime)` → `AnimationMixerPlayable.Create(graph, 3)` → `AnimationPlayableOutput.Create("Animation", animator)` → `output.SetSourcePlayable(_mixer)` → `_graph.Play()`。
2. **首次播放**：`PlayXXX` 从对象池取节点（`ResSystem.GetOrNew<T>()`），`node.Init(graph, _mixer, …, inputPort: _fromPort)`，把节点子图接到主混合器端口，`_mixer.SetInputWeight(_fromPort, 1)`，赋给 `_currentNode`——**首次不做过渡**。
3. **后续播放**：节点同样 `Init`，但 `inputPort` 传 `_toPort` 且 `isTransitioning: true`；`ConnectToPlayableGraph` 在 `isTransitioning` 时直接 `return`（接线推迟到过渡协程），随后 `RenewNextNode` 入队（重复节点会被 `IsSameNode` 去重）。`LockTransition` 为真时直接丢弃。
4. **每帧驱动**：`Animation_Controller.Update` 中，若 `_nextNode != null` 调 `UpdateTransitionAnimation`（首帧启动协程；`_transitionBreaking` 时把 `_previousNode` 权重清零、当前节点权重置 1 并重启协程），再驱动 `_curAnimationChain.UpdateChain()`。
5. **过渡**：`TransitionAnimation` 先销毁上一个 `_previousNode`，`previous = current; current = next; next = null`；若 `current is ICanSyncNode` 则按其 `IsSync` 调 `SetSyncing`；`current` 未接线则 `ConnectToPlayableGraph(_mixer, _graph, false)`；交换 `_fromPort/_toPort`；协程内每帧 `currentWeight -= Time.deltaTime * Speed / fixedTime`，`previous` 权重重 1→0、`current` 0→1。
6. **混合参数更新**：由业务层每帧调用节点的 `SetBlendAnimationAsLinerPoint` / `SetClipsWeights` / `SetBlendByXAndY` 等改写各层 mixer 权重；开启 `isSync` 的节点在接线时 `this.AddUpdate(SyncPhase)`，即相位同步跑在 `MonoSystem` 的全局 update 事件上，而非本控制器。
7. **销毁**：`DestroyNode(node)` → `_graph.Disconnect(_mixer, node.InputPort)` + `node.PushPool()`（`IsCached` 的节点在非强制回收下只置 `IsLinked = false` 并保留 Playable）；`Recycle`/`DestroyGraph` 对三个节点 `PushPool(true)` 后 `_graph.Destroy()`。

## 关键机制详解

### 1. 双端口主混合器 + 线性协程过渡

主混合器只有 0/1 两个端口在用（创建时给了 3 个输入，第三个未使用），当前节点占一个、待播节点占另一个，过渡即两端权重互补：

```csharp
(_fromPort, _toPort) = (_toPort, _fromPort); // 提前交换防止协程被打断后端口错位
float currentWeight = 1;
var speed = 1 / fixedTime;
while (currentWeight > 0)
{
    yield return null;
    currentWeight = Mathf.Clamp01(currentWeight - Time.deltaTime * Speed * speed);
    if (_previousNode != null) _mixer.SetInputWeight(_previousNode.InputPort, currentWeight);
    _mixer.SetInputWeight(_currentNode.InputPort, 1 - currentWeight);
}
```

`CheckIsTransitionFinished` 用交换后的 `_fromPort` 权重是否约等于 1 来判断（命名与实际含义相反，容易误读）。

### 2. 二维混合树的权重算法

`TwoDimensionalTransitionContainer.GetWeights`：以 `Points[0]` 为公共顶点，从移动点分别向顺时针/逆时针找夹角最小的两个采样点构成三角形，再用重心坐标求三点权重（`CalculateWeights`），退化时兜底为最近顶点。`Create` 阶段强校验：**首点必须是 `(0,0)`、点数必须 >3、相邻点角度差不得大于 180°**，否则直接抛 `ArgumentException`。

### 3. 方向性线性混合

`DirectionalLinearBlendTreeNode` 是"两层一维"：外层对 `_totalMixer` 按移动速度点（`_yBlendContainer`）混合各速度层，内层对每层 mixer 按转向点（`_xBlendContainers[i]`）混合方向片段。`SetBlendByXAndY(movePoint, turnPoint)` 的实参顺序是（转向 X，移动 Y）→ `ApplyBlendByXAndY` 先 `SetClipWeightAsLinerPointInternal` 刷所有层的内层权重，再 `SetBlendAnimationAsLinerPointWithoutSync` 刷外层，最后 `SyncWhenMainClipChange`。

### 4. 上下半身分离

`UpperLowerMixerAnimationNode.InitializeUpperMixer` 建 `AnimationLayerMixerPlayable.Create(graph, 2)`：第 0 层接下身混合树（权重 1），第 1 层接 `_upperMixer`（两个 `AnimationClipPlayable` 端口交替使用）并用 `SetLayerMaskFromAvatarMask(1, avatarMask)` 限定骨骼范围。换上身片段时把新片段接到空闲端口，用 `MonoSystem.Start_Coroutine` 跑 `TransitionUpperAnimation` 做权重交叉淡入，而非在控制器层过渡。

### 5. 相位同步（ICanSyncNode）

接口只声明 `bool IsSync { get; }`，真正的同步逻辑落在两个混合节点的 `SyncPhase`，分两级：

```csharp
var localMasterNorm = (float)((localMasterPlayable.GetTime() % localMasterClip.length) / localMasterClip.length);
var localPhaseAnchor = localMasterNorm - deviations[localMasterClipIndex];
// 层内：其它片段 = 锚点 + 自身相位差
var normalizedTime = (localPhaseAnchor + deviations[clipIndex] + 1f) % 1f;
playable.SetTime(normalizedTime * clip.length);
```

```csharp
SyncMixerInternalByLocalMaster(...);      // 先层内对齐
SyncLocalMastersToGlobalMaster(...);      // 再把各层"本地主片段"对齐到全局主片段
SyncMixerInternalByLocalMaster(...);      // 最后再按新主片段重复层内对齐
```

主片段由"有效权重 = 层权重 × 片段权重"取最大者确定，并带**防抖**：候选需领先当前主片段权重 ≥0.08 且距上次切换 ≥0.15s（层内为 0.12s）才允许切换，避免临界权重抖动。

### 6. 梯度带插值（Gradient Band）

`GradientBand` 对固定 `POINT_COUNT = 4` 个采样点，把"采样点→边界点"的半平面距离取 `1 - 投影比` 并 `Clamp01`，对各方向取最小值，最后归一化，得到 C0 连续、边界处为 0 的权重场；极坐标版把幅值/角度各自归一化后拼成 2D 向量再算（角度乘 2 倍系数）。**⚠ 待确认：全项目检索不到任何调用点，当前应属预留/未接线**。

## 对外 API 与扩展点

- **新增一种混合节点**：继承 `BlendAnimationNodeBase`（需要同步则实现 `IsSync` 并在 `ConnectToPlayableGraph` 里 `this.AddUpdate(SyncPhase)`；不需要同步可只继承 `AnimationNodeBase`，参考 `UpperLowerMixerAnimationNode`）。必须实现 `ConnectToPlayableGraph<V>(V outputMixer, PlayableGraph graph, bool isTransitioning)`、`SetClipSpeed`；按需覆写 `SetBlendAnimationAsLinerPoint`、`SyncWhenMainClipChange`、`PushPool`。
- **注册到控制器**：在 `Animation_Controller` 加 `PlayXxx(...)`：首播分支用 `_fromPort` + `isTransitioning:false`，非首播用 `_toPort` + `isTransitioning:true` 再 `RenewNextNode(node, transitionFixedTime, transitionBreaking)`；节点经 `ResSystem.GetOrNew<T>()` 获取、`PushPool` 归还。
- **接进播放链**：新增 `AnimationChainNode<T>` 子类并在 `AnimationChain` 加重载 `ConnectNextNode`（现有单片段/方向/二维/二维外一维内四种）。
- **新增动画配置**：继承 `FrameConfigBase`（`SerializedScriptableObject`），加 `[CreateAssetMenu]` 与 `[FrameConfig(typeof(X), "AnimationConfig/X")]`，然后在 `CharacterAnimationConfig` 加 `[OdinSerialize]` 字典 + `TryGetXxx` 方法。
- **动画事件**：`AddAnimationEvent(name, Action/Action<T>)`；clip 上的事件函数名固定为 `AnimationEvent`，`stringParameter` 以 `/` 分隔"事件名/字符串参数"。

## 与其他模块的耦合

- **MyFrameRoot**：初始化序列（Save→Pool→Event→UI→Mono→Audio→Time）中不含动画，动画控制器由业务显式 `Init`，因此不依赖 root 的启动顺序。
- **MonoSystem**：`AddUpdate/RemoveUpdate`（相位同步注册到全局 update）、`Start_Coroutine/Stop_Coroutine(this, …)`（上身过渡与控制器自身过渡协程）。
- **PoolSystem / ResSystem**：所有节点、播放链节点均走 `GetOrNew` + `ObjectPushPool` 回收。
- **配置层**：`FrameConfigBase` + `FrameConfig` 特性，Demo 层通过 `CharacterAnimationConfig` 按名字取片段/混合树。
- **Animator**：仅作输出端（`AnimationPlayableOutput`）与根运动来源，`OnAnimatorMove` 中按 `SetSyncClampSpeed` 限幅后回调 `SetRootMotionAction` 注册的委托。

## 设计亮点与可改进点

**亮点**

1. 节点即子图：每个节点自建 mixer/clip playable 并只暴露"接哪根线"，组合维度扩展成本低。
2. 双端口 + 可打断协程，过渡与混合解耦；`EnsureAnyWeight` 专门处理"全零权重导致首帧空输出"这一 Playable 常见坑。
3. 相位同步做成 local→global 两级 + 权重/时间双阈值防抖，比单纯 `SetTime` 对齐稳健。
4. 二维权重容器在 `Create` 阶段做几何合法性校验，配置错误在初始化时暴露而非运行时静默出错。

**可改进**

1. 目录内所有类型**都在全局命名空间**（文件里只有 `using MyFrame;`，没有 `namespace MyFrame`），与"框架命名空间 MyFrame"的约定不一致。
2. `GradientBand` 无调用点，属死代码/预留，建议标注或接入二维混合。
3. `_mixer = AnimationMixerPlayable.Create(_graph, 3)` 但只用 0/1 两端口；`_fromPort/_toPort` 在过渡中交换后语义反转，`CheckIsTransitionFinished` 读起来与直觉相反。
4. `AnimationNodeBase.PushPool(bool isForced)` 忽略 `isForced`，`DestroyGraph` 里的 `PushPool(true)` 对缓存节点是否真正释放取决于各子类实现，容易漏。
5. `fixedTime == 0` 时 `speed = 1 / fixedTime`（∞）仍进入 while 循环，白跑一帧；可提前 `yield break`。
6. **⚠ 待确认**：`SingleAnimationNode.NormalizedTime` 未对 `1` 取模，循环片段播放超过一轮会 >1，而播放链用 `>= EndNormalizedTime` 判断结束，语义上依赖"首轮即结束"。
7. **⚠ 待确认**：`SyncPhase` 直接 `SetTime` 硬置时间，与 `SetClipSpeed`/图时间推进的相互作用（是否造成速度抖动）未见处理说明。
