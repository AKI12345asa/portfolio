# 08 其他子系统与基础设施

## 一句话定位

除存档、对象池、事件、UI 之外，MyFrame 的其余支撑层：**时间缩放、集中式生命周期、音频门面、泛型状态机、行为优先级仲裁、资产化配置、输入映射，以及一批反射与工具**。它们由 `MyFrameRoot` 按固定顺序初始化，共同撑住"业务类不继承 MonoBehaviour 也能跑起来"。

## 各子系统详解

### TimeSystem：两级时间缩放与顿帧

**问题**：一处控世界流速，同时给每个实体独立局部倍率，并把变化通知表现层。

**用法**：实现 `ITimeOwner`（`timeScaleContainer` + `WhenUpdateTimeScale`）后 `RegisterAsTimeOwner(this)`，推进统一用 `GetDeltaTime()`，`SetTimeScale`/`SetWorldTimeScale` 分别改局部与全局；注销后容器标 `Abandon`，再用即抛异常。

**实现**：`GetTimeScale = ImpactByWorldScale ? 局部 × 全局 : 局部`——**是两级相乘，不是多套独立时钟**：所有 owner 共享同一 `Time.deltaTime` 与同一静态 `WorldTimeScale`，场景名只用于分桶。顿帧由 `ReceiveShutter`/`SetShutter` 托管 `IFrameStutter` 的协程，`WaitForSecondsRealtime` 使顿帧时长本身不受缩放影响。

**与 Skill_Player 的关系**：`_playTotalTime += _owner.timeScaleContainer.GetDeltaTime()` 再乘 `FrameRate` 得帧号，技能时间轴直接挂在宿主的局部缩放上；`WhenUpdateTimeScale` 只把倍率写进 `AnimationController.Speed`。

**示例**：`TimeSystem.SetTimeScale(player, 0.1f)` 让该角色变慢而其它人正常。

⚠ 两个顿帧字典命名与内容相反；`RegisterAsTimeOwner` 用 `TryAdd`，重复注册会让 owner 容器与字典错位。

### MonoSystem：集中式生命周期驱动

**问题**：让状态、技能行为、纯 C# 类也拿到 Update 与协程，不必各自挂空 MonoBehaviour。

**用法**：`this.AddUpdate(() => Tick())` / `RemoveUpdate`；协程 `MonoSystem.Start_Coroutine(this, routine)` 按 key 登记，`Stop_Coroutine(this)` 停该 key 全部协程。

**实现**：三个空 `Update/FixedUpdate/LateUpdate` 只把三个 `static event Action` 转发出去；`Init` 取 `MyFrameRoot.Instance` 的组件实例、把 event 置空（防编辑器重复 Init 叠加），并借 PoolSystem 预建 `List<Coroutine>` 池。

**示例**：非 MonoBehaviour 的 `StateBase` 只靠 `this.AddUpdate(Update)` 就有逐帧回调。

⚠ 单参 `Start_Coroutine` 不登记 key；`FrameExtension.AddUpdate` 的 `this` 被忽略，注销要手工 `Remove`。

### AudioSystem / AudioModule：音量组与播放器池

**问题**：BGM 与一次性音效分开管理，统一音量（全局 × 分类）、静音、暂停与淡入淡出，并复用播放器。

**用法**：`AudioSystem.PlayBGAudio(clip, loop, volume, fadeOut, fadeIn)`、`PlayBGAudioWithClips(clips)`、`StopBGAudio`；音效 `PlayOneShot(clip, component 或 position, autoReleaseClip, volumeScale, is3d, callBack)`。`AudioSystem` 只是转发门面，`Init` 时在 Root 下找 `AudioModule`。

**实现**：不用 AudioMixer，而是**乘法音量组**——BGM 为 `bgVolume × globalVolume`、音效为 `effectVolume × globalVolume`，字段都带 Odin `OnValueChanged`，Inspector 拖动即时试听。BGM 独占一个 AudioSource，切换由 `DoVolumeFade` 淡出→换 clip→淡入；**音效走对象池**（`GameObjectPoolModule`，池名 `AudioPlayPool`，默认 20），播完按 `clip.length` 延迟回收，绑定宿主时 reparent、宿主销毁由 `FrameEventExtend.OnDestroy` 抢回。

**示例**：`AudioSystem.PlayOneShot(hitClip, enemy.transform, volumeScale: 0.8f);`

⚠ `StopBGAudio` 调的 `MonoSystem.Stop_Coroutine(coroutine)` 会命中单参重载 `Stop_Coroutine(object)`，协程被当成字典 key 而注册时未带 key，**循环协程实际停不下来**；`audioPlayRoot` 只在 `AudioPlayerPoolRoot` 不存在时才创建，预制体两节点都已存在，该字段可能为 null。

### StateMachine：泛型状态机

**问题**：给"一个宿主 + 一组枚举状态"提供非 MonoBehaviour、可池化的状态机，状态的 Update 由框架驱动。

**用法**：`MyFrame.StateMachine.CreateMachine<TOwner, TStateBase, TEnum>(this)` → 逐个 `RegisterState<TOwner, TEnum, TStateBase, TState>(TEnum.Xxx)` → `ChangeState(enum, reCurrState)` → `Stop()`/`Destroy()`；状态继承 `StateBase<TOwner, TState>`，宿主实现空标记接口 `IStateMachineOwner`。

**实现**：`ChangeState` 依次 `CheckCanEnterState` → 旧状态 `BeforeExit(新)` → 新状态 `BeforeEnter(旧)` → `Exit`/`Enter` → 把 `state.Update/LateUpdate/FixedUpdate` 通过 `FrameExtension` 挂到 MonoSystem，切走时精确解绑；实例与状态字典来自 `ResSystem.GetOrNew`，`Stop` 时归还对象池。

**示例**：目标状态未注册时 `ChangeState` 直接抛 `KeyNotFoundException`，注册必须早于首次切换。

### BehaviourExecutor：行为优先级仲裁

**问题**：同一时刻只允许一个行为（Action 委托）生效，新行为凭优先级或 checker 抢下当前行为，如"翻滚打断攻击""受击打断一切"。

**用法**：`var h = Player.ExecuteBehaviour(() => ChangeState(Attack), priority: 2f, checker: StateChecker, behaviourID: "Attack");`，用 `h.State` 判 `Failed/Working`，结束调 `h.SetBehaviourEnd()`；同 ID 的重复请求直接复用当前 handler。

**实现**：**不是任务队列，也不跑协程**——只做仲裁（`Checker` 返回 false 即失败，否则比 `Priority`）与持有（`_curBehaviourHandler` 单槽），通过的瞬间 `Action?.Invoke()` 同步执行，之后无轮询。**与状态机的关系**：`DemoPlayerStateBase` 在 `Enter`/`Update` 里用 `Priority + StateChecker` 申报"本状态要占用的行为"——状态机决定"我是谁"，Executor 决定"能否落地"。

**示例**：低优先级的"移动"申报会被正在 Working 的攻击挡回 `Failed`，由调用方重试。

⚠ 抢占失败与被抢占的 handler 都没 `End`/`Destroy`；构造函数每次 new 都重复建同名池。

### Config：FrameConfigBase / MyFrameSetting / ConfigWindow

**问题**：所有项目数据都以 ScriptableObject 资产存在、按文件夹白名单被扫描、在统一窗口里浏览编辑。

**用法**：新建类继承 `FrameConfigBase`，打上 `[FrameConfig(typeof(Xxx), "大组/小组")]`，把 `.asset` 放进 `MyFrameSetting.ConfigFolderPathList` 的文件夹，即出现在 FrameWindow → Config 页。

**实现**：`FrameConfigBase` 只继承 Odin 的 `SerializedScriptableObject`，把"可序列化字典 + AssetDatabase 可扫"统一起来；`MyFrameSetting` 是唯一的框架级实例（`FramePerSecond`、`UIWindowDataDic`、`UILayoutDataList`、`SaveSystemType`、`ConfigFolderPathList`）。`FrameWindowUtility.InitConfigInspector()`（`[InitializeOnLoadMethod]`）用 `GetTypesByBaseTypeAndAttribute<FrameConfigBase, FrameConfigAttribute>` 扫全程序集，把 `"技能/技能配置"` 拆成 `ConfigGroupItem` 树、把 `[FrameConfigInspector]` 映射成面板；资产列表由 `FindAllInFolders<FrameConfigBase>(ConfigFolderPathList)` 得到，右侧默认用 Sirenix `PropertyTree.Draw()`。

**示例**：右键配置树节点 → "新建该类型资产" → AddConfigPanel 选类型/路径/名字 → `AssetDatabase.CreateAsset` 后刷新列表。

⚠ `GetTypesByBaseTypeAndAttribute` 判断的是 `type.BaseType`，只匹配**直接基类**，间接继承的配置类不会进树。

### Input：InputManager / KeyConfig

**问题**：把"按键 → 回调"的绑定、上下文开关与改键监听收口到一处。

**用法**：`InputManager.BindKeyboardKey(keyConfig.defaultKey, OnAttack, keyConfig, checker)` / `BindMouseKey`，由它每帧轮询回调，`RemoveKey` 解绑；查绑定用 `GetKeyByConfig`/`GetKeyByConfigId`；改键用 `StartListeningInputKey` + `RegisterKeyListeningEvent`。

**实现**：`KeyConfig` 是资产里的配置项（响应类型、`isCache + cacheTime`、`keyType`、`defaultKey/defaultMouseID`、`keyName`、`keyGuid`），`KeyConfigs : FrameConfigBase` 持列表，Odin 的 `CustomAddFunction` 新增时用 `GUID.Generate()` 生成 keyGuid。运行时是 `action → List<KeyData>` 加 `keyGuid → KeyData` 双向字典；`Update` 先 `KeyData.Update()` 记按/抬时间供 `cacheTime` 判定，再按响应类型触发，每 action 每帧最多回调一次。

**示例**：改键面板靠 `_keyDataWithConfigId` 拿到某配置项此刻绑定的 `KeyData` 回显。

⚠ `cacheTime` 是"时间窗"语义（窗口内 `GetKeyDown` 一直为 true）而非"缓存一次按下"；`KeyData.IfCached` 只看 `bindConfigGuid != null`；`ICanInputComponent` 无实现者。

### Tool：五个静态工具

`CameraBezierTool.Evaluate` 三次贝塞尔取点（控制点为相对端点偏移）；`CoroutineTool` 复用 `WaitForEndOfFrame/WaitForFixedUpdate` 实例并手写 `WaitForSeconds/WaitForSecondsRealtime/WaitForFrames`；`FrameMathTool` 提供 2D 点绕定点旋转与任意阶贝塞尔 Bernstein 权重；`MeshGenerator.GenerateFanMesh` 按内/外半径、高度、角度生成扇形环带 Mesh（2.5° 一段）；`SkillGizmosTool.DrawDetection`（仅编辑器）按 `AttackDetectionType` 画武器碰撞体/盒/球/扇检测体。

### Utility / Extension：反射扫描与 this 扩展

**FrameUtility** 是"零改动接入"的地基：`GetTypesByAttribute<T>` 扫全程序集找打了特性的类型并**同时吐出特性实例**；`GetTypesByBaseTypeAndAttribute<B,T>` 再要求直接基类为 `B`（窗口表、配置树都走它）；`GetTypesByBaseType<B>` 只要类型；`FindAllInFolders<T>` 封装 `AssetDatabase.FindAssets`；`GetInterfaceMethods<I>(methodName, containAbstract)` 用 `Type.GetInterfaceMap` 把"接口方法名"映射成各实现类的 `MethodInfo`，默认跳过抽象实现——拿到 `MethodInfo` 就能对一批互不相关的类型统一 `Invoke`/建委托，这是"按约定调用而不是硬编码类型"的钩子。

⚠ `GetTypesByAttribute`、`GetTypesByBaseType`、`GetInterfaceMethods` 在仓库内**没有调用点**，真正在用的是 `GetTypesByBaseTypeAndAttribute`（窗口表、配置树、Inspector 映射）与 `FindAllInFolders`（配置资产列表）。

其余：两个 `FrameConfig*Attribute` 是注册表的数据源；`FrameExtension` 把 PoolSystem/MonoSystem 包成 `this` 扩展并提供 `GetDerivedClasses`（抽象泛型基类自动展开为具体子类）；`SingletonMono<T>` 在 `Awake` 里"第一个赢"、后来者 `DestroyImmediate`，全框架只有 `TimeSystem` 与 `InputManager` 用它。

### FrameWindow：编辑器主窗口

MenuItem `MyFrame/Open FrameWindow` 打开，左侧 ToolbarButton 切 Config / Setting 两页，uxml 从 `Assets/MyFrame/Editor/WindowAsset/FrameEditorWindow.uxml` 硬编码加载。Setting 页里 WindowDic 整块 `SetEnabled(false)`（标题写明"由数据生成、不支持修改"）、LayoutDic 可增删 `UILayoutData` 并调 `UISystem.Instance.RefreshUISystem()` 重建 UI 层、存档方式下拉写 `Setting.SaveSystemType`、`ConfigFolderPathList` 用 `EditorUtility.OpenFolderPanel` 加白名单；Config 页交给 `ConfigWindow`（左树 / 中列表 / 右属性面板）。

⚠ `SettingEditor` 里"当前窗口已经开启"那段只有 `Debug.LogWarning`，不阻止任何操作。

### MyFrameRoot：初始化顺序与编辑器引导

**单例与常驻**：`Awake` 里 `Instance == null` 则赋值 + `DontDestroyOnLoad(gameObject)` + `InitSystems()`，否则 `Destroy(gameObject)`；`[DefaultExecutionOrder(-20)]` 保证早于普通脚本，`[DisallowMultipleComponent]` 加 `Reset` 里的 `delayCall` 去重兜底。

**初始化顺序**：`SaveSystem → PoolSystem → EventSystem → UISystem → MonoSystem → AudioSystem → TimeSystem`，顺序有依赖：MonoSystem 借 PoolSystem 建协程 List 池，AudioSystem 借 PoolSystem 建播放器池，UISystem 读 Setting；各系统都是 static 门面，`Init` 时自己到 Root 下找宿主组件。

**WindowDataDic**：静态属性直接指向 `setting.UIWindowDataDic`（为空则 new）；`InitWindowDataInConfig()` 用 `GetTypesByBaseTypeAndAttribute<UIWindowBase, UIWindowDataAttribute>` 扫全程序集，把特性的 `windowKey/ifCache/layerNum/assetPath/ifPreInit` 组 `UIWindowData` 填表，UISystem 只读这张表开窗——**新增窗口 = 加一个带 `[UIWindowData]` 的 `UIWindowBase` 子类**，无需改注册代码。

**编辑器引导**：`[InitializeOnLoad]` 的 `EditorBootstrap` 加一个 `[InitializeOnLoadMethod]` 入口（`s_EditorCallbacksRegistered` 防重复），挂 `delayCall / hierarchyChanged / sceneOpened / playModeStateChanged`；回调里用 `Resources.FindObjectsOfTypeAll<MyFrameRoot>()` 找场景实例，补齐 `Instance` 后跑 `InitSetting()` + `InitSystems()`，成功后摘掉回调。

⚠ 运行时 `Awake` 只调 `InitSystems()`、**不调 `InitSetting()`**，窗口表依赖编辑器生成后序列化进 setting 资产；`InitWindowDataInConfig` 内没有 `SetDirty(Setting)`，落盘时机不确定。

## 与其他模块的耦合

- **MyFrameRoot** 是所有系统 Init 的调度者，也是 `MyFrameSetting` 的唯一持有者：`UISystem`/`AudioSystem`/`SaveSystem`/`FrameWindow` 都经它取数据与宿主。
- **MonoSystem ← PoolSystem / FrameExtension / StateMachine / AudioModule**：协程 List 池来自 PoolSystem，`StateBase` 的 Update 由 `AddUpdate` 挂入。
- **AudioModule → PoolSystem / ResSystem / EventSystem**：`GameObjectPoolModule` 管播放器，`ResSystem.UnloadAsset` 释放 clip，宿主销毁靠 `FrameEventExtend.OnDestroy` 接管。
- **TimeSystem ← ITimeOwner（PlayerController / DemoEnemyController / Skill_Player）与 IFrameStutter（StutterFrameProcessor 触发顿帧）**：倍率最终落到 `AnimationController.Speed` 与各处 `GetDeltaTime()` 步长。
- **StateMachine → ResSystem + MonoSystem**；**BehaviourExecutor → PoolSystem**，唯一出口是 `PlayerController.ExecuteBehaviour`，被状态基类、技能行为、ActionModule 共用。
- **Config 体系 ← FrameUtility 反射**：配置树、Inspector 映射、资产列表三处都没有显式注册表；`ConfigFolderPathList` 与 `SaveSystemType` 又反向影响扫描范围与存档行为。
- **Input 与其余部分近乎解耦**：独立门面，仅 `PlayerController` 使用，不进 `InitSystems`。

## 设计亮点与可改进点

**亮点**：① **特性即注册表**——窗口表、配置树、自定义面板三套注册全靠"扫程序集 + 读特性"，新增类型零改动接入；② **时间缩放做成"容器 + 回调"**——逻辑侧只认 `GetDeltaTime()`、表现侧只认 `WhenUpdateTimeScale`，顿帧不用改业务代码；③ **业务不继承 MonoBehaviour**——Update 被 static event 收拢，状态机/技能/行为都是普通 C# 类且走池化，切换状态无 GC。

**可改进点**

> **状态更新**：本清单是首次通读时的记录。其中第 2、3、4 条（`StopBGAudio` 协程传参、`BehaviourExecutor` 回收漏项、TimeSystem 注册与顿帧字典）**已在后续版本修复**，保留在此仅作为问题记录。其余为命名空间与工程规范类的观察。

1. **命名空间不统一**：`TimeSystem`/`ITimeOwner`/`InputManager`/`KeyData` 在全局命名空间，其余在 `MyFrame`；`MyFrame.BehaviourExecutor` 里还有同名类，`namespace MyFrame` 内会被解析成命名空间。
2. **`MonoSystem.Stop_Coroutine` 缺单参重载**，导致 `AudioModule.StopBGAudio` 静默失效。
3. **`BehaviourExecutor` 回收缺口**：抢占失败与被抢占的 handler 都没 `End`/`Destroy`；每次 new 都重复建同名池。
4. **`TimeSystem` 细节**：重复注册时容器错位、顿帧两字典命名相反、`SetShutter` 会重启旧 Getter 协程。
5. **编辑器引用未隔离**：`MyFrameSetting.cs`、`FrameUtility.cs`、`KeyConfigs.cs` 直接 `using UnityEditor` 而无 `#if UNITY_EDITOR` —— ⚠ 待确认（未实际构建验证）。
6. **反射 API 疑似死代码**：`GetTypesByAttribute`/`GetTypesByBaseType`/`GetInterfaceMethods` 全仓库无调用点。
