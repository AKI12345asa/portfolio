# 02 战斗与技能系统

## 一句话定位

MyFrame 战斗运行时是一套「**Clip 数据 + 帧时间轴 + 帧事件 + 可注册处理器**」的技能播放框架：`SkillClip` 只记录每条轨道第几帧发生什么，`Skill_Player` 按帧推进并分发，`SkillBehaviourBase` / `SkillBrainBase` 承载单个技能的逻辑与决策，伤害、音效、特效、顿帧、镜头等具体表现由 Processor 完成。

## 运行流程

1. **决策**：`SkillBrainBase.ReleaseSkill(SkillConfig)` 为抽象方法，由具体 Brain 实现（Demo 中按优先级挑行为、检查 CD/按键）。它先在 `SkillPlayer.StartPlayerSkillBehaviour(behaviour)` 里绑定当前行为节点，再调用 `PlaySkillClip(clip, isLoop)`。
2. **起播**（`PlaySkillClip`）：结束残留相机事件 → 清帧索引/计时/已完成的相机事件 → 记 `_frameRate`、`_isPlaying = true` → `_curSkillCamera?.StartSkillCamera()` → 停武器探测 → **立即 `TickSkill()` 播第 0 帧** → `UpdateCameraEvents()`。
3. **谁 Tick 谁**：唯一推进者是 `Skill_Player.Update()`（MonoBehaviour）。它用 `_owner.timeScaleContainer.GetDeltaTime()` 累加 `_playTotalTime`（因此受 TimeSystem 时间缩放/顿帧影响），算出 `targetFrameIndex = _playTotalTime * _frameRate`，再用 `while (_currentFrameIndex < targetFrameIndex)` 逐帧补 `TickSkill()`——**一帧 Update 可推进多帧**，掉帧不会漏事件，但一次 Update 内会连续触发多个帧事件。行为节点自身不由 Skill_Player 调 `OnUpdate`，而由 `SkillBrainBase.Update` 遍历 `SkillBehaviourDic` 驱动。
4. **帧内顺序**（`TickSkill`，固定顺序）：`_skillBehaviour.OnTickSkill(frameIndex)` → `TickSkillCustomEvent` → `TickSkillAnimationEvent` → `TickSkillAudioEvent` → `TickSkillEffectEvent` → `TickSkillAttackDetectionEvent` → `_currentFrameIndex++`。
5. **取帧方式**：动画与自定义事件是 `Dictionary<int,...>`，按当前帧精确取值；音频、特效、检测是 `List`，每帧全量遍历并用 `FrameIndex`（检测还含 `DurationFrame` 区间）过滤。
6. **无「前摇/判定/后摇」枚举**：代码中没有阶段状态机，所谓前摇/判定/后摇完全由 Clip 内各轨道事件的帧位置表达，逻辑分段由 `SkillCustomEvent`（`UnFreezeSkillRelease` / `CanRotate` / `CantRotate`）在行为侧打点。
7. **结束**：非循环且 `targetFrameIndex >= FrameCount` → `Clean()`（清 `_skillClip`、`_isPlaying=false`）→ `_skillBehaviour.OnSkillClipEnd()` → 行为侧 `OnClipEndOrReleaseNew` + `Owner.OnSkillEnd()`，并置 `SkillBrain.Exiting = true`（Brain 在下一帧 `Update` 里等动画过渡完成后 `EndSkillState`）。循环时 `ResetLoopFrame` 把帧与时间同时回退、清检测与相机状态。`StopCurrentSkill()` 是外部强打断入口。
8. **单次命中链**：检测到 `IHitTarget` → `SkillBehaviourBase.OnDetection`（去重 + `Owner.OnAttack`）→ `OnHitTarget` → `hitTarget.BeHit(hitPoint, out data)` → `SkillPlayer.InvokeHitTargetEvent(data)` → 之后才遍历 `detectionEvent.TriggerEvents` 找已注册处理器执行。

## 关键机制详解

### 1. 用时间累加而非帧计数推进，支持时间缩放

```csharp
_playTotalTime += _owner.timeScaleContainer.GetDeltaTime();
var targetFrameIndex = (int)(_playTotalTime * _frameRate);
while (_currentFrameIndex < targetFrameIndex && _isPlaying)
{
    if (_currentFrameIndex >= _skillClip.FrameCount)
    {
        if (!IsLoop || _skillClip.FrameCount <= 0) break;
        ResetLoopFrame(ref targetFrameIndex);
    }
    TickSkill();
}
```

帧索引由时间反推，因此慢动作/顿帧只改变 `_playTotalTime` 的增长速率；`ResetLoopFrame` 同时修正 `targetFrameIndex` 与 `_playTotalTime`，避免循环后一瞬间追帧。

### 2. Before/After 钩子：行为可在播放中途改写或吞掉帧事件

六类帧事件都是先 `Before*Event`，返回 `null` 即丢弃，再执行，最后 `After*Event`：

```csharp
skillAnimationEvent = _skillBehaviour.BeforeSkillAnimationEvent(skillAnimationEvent, out var autoPlayAnimation, out var setWeaponHand);
if (skillAnimationEvent == null) return;
if (setWeaponHand) SetMainWeaponHand(skillAnimationEvent.MainWeaponOnLeftHand);
if (autoPlayAnimation) { /* PlaySingleAnimation + SetClipSpeed */ }
if (skillAnimationEvent.ApplyRootMotion) animationController.SetRootMotionAction(_skillBehaviour.OnRootMotion);
else animationController.ClearRootMotionAction();
_skillBehaviour.AfterSkillAnimationEvent(skillAnimationEvent);
```

`out` 参数让行为能「只换参数不改事件」。这使同一份 Clip 可被不同行为复用（例如同一段动画在不同角色上以不同速度/根运动策略播放）。

### 3. 攻击检测双通道：武器 trigger 与形状扫描

- **Weapon**：只在事件起始帧 `StartDetection` 打开 `SkillChecker.detectionCollider`，在 `FrameIndex + DurationFrame` 帧关闭。命中由 `SkillChecker.OnTriggerStay` 中 `LayerMask` 位与 + `ClosestPoint` 计算命中点后回调。
- **Box/Sphere/Fan**：每帧在区间内用 `SkillAttackDetectionTool` 做 `Overlap*NonAlloc`（固定 20 槽静态数组，零 GC），扇形用「外接盒 + 内外半径 + 夹角」二次过滤，并用「末位换位」原地压缩结果。

两条通道最终都汇入 `SkillBehaviourBase.OnDetection`，用 `DetectionEventHitTargets[event].HitTargets`（`HashSet<IHitTarget>`）去重；`PlayingOnUpdate` 按 `ComboCheckDeltaTime`/`CheckCount` 周期性清空集合，从而支持连击多段命中同一目标。

### 4. 事件 → 处理器：注册表 + 泛型类型键，双向解耦

```csharp
public void RegisterDetectionEventProcessor<T>(DetectionEventProcessor<T> processor) where T : DetectionTriggerEventBase
    => _attackDetectionEventProcessorDic.TryAdd(typeof(T), processor);

// 分发侧
foreach (var triggerEvent in detectionEvent.TriggerEvents)
    if (_attackDetectionEventProcessorDic.TryGetValue(triggerEvent.GetType(), out var p))
        p.ProcessEvent(triggerEvent, hitPoint, hitTarget, this);
```

数据（`DetectionTriggerEventBase` 派生类）只描述「要发生什么」，处理器描述「怎么发生」，两者只靠 `Type` 关联。处理器在构造函数注入 `ICharacter Owner`，注册点在角色控制器（Demo 中 `PlayerController.RegisterDetectionEventProcessor(...)` 注册 5 个，敌人只注册 4 个，缺 `ImpulseEventProcessor`——**按需装配**正是该设计的收益）。未注册的类型静默跳过，不报错。

### 5. 相机事件改造为「秒制时间轴 + 四段生命周期」

相机事件不走帧字典，而是每帧 `UpdateCameraEvents` 用 `CreateCameraEventTime` 把 `FrameIndex/FrameRate` 换算成 `CameraEventTime`（`StartTime`/`Duration`/`PlaybackTime`，含 `Progress`），再依次 `StartEvent`（首次到达）、`TickEvent`（区间内每帧）、`EndEvent`（到达结束或被中断）；`_finishedCameraEvents` 保证不重复触发。`CameraResetEventProcessor` 调 `ResetTriggeredCameraProcessors()`，由各处理器的 `ResetProcessor` 撤销 FOV/旋转等副作用——**只有被触发过的处理器才会被复位**。`SkillCamera.LateUpdate` 负责跟随与 `HoldWorldPosition/Rotation`，因为相机可能是宿主子物体。

### 6. 行为节点与大脑的分工

`SkillBehaviourBase` 是**原型可拷贝的逻辑节点**（`DeepCopy` + `Init(owner, brain, skillPlayer)`），一个行为对应一个 `SkillConfig`，由 `SkillBrainBase.SkillBehaviourDic` 持有；Brain 的 `Update` 是行为 `OnUpdate` 的唯一驱动源。生命周期：`Release`（开始，清去重表、冻结再次释放）→ `PlayingOnUpdate`（每帧，去重倒计时）→ `OnSkillClipEnd` / `OnNextReleaseSkill` / `OnClipEndOrReleaseNew` → `OnSkillBehaviourStopped`（被打断，解冻）。`SkillBrainBase` 还兼作**技能内共享数据总线**：`Dictionary<string, ISkillConfigData>` + `SkillShareData<T>` 池化泛型包装，避免装箱并提供 创建/变更/移除 三组事件。

## 与其他模块的耦合

- **动画系统**：`Animation_Controller.PlaySingleAnimation(clip, transitionFixedTime, refreshAnimation, transitionBreaking)` + `SetClipSpeed`、`SetRootMotionAction`/`ClearRootMotionAction`、`CheckIsTransitionFinished`（Brain 判断能否退出技能状态）。根运动回调进 `SkillBehaviourBase.OnRootMotion` → `ICharacter.OnSkillMove/OnSkillRotate`。
- **事件系统**：本模块**不使用** EventSystem 全局总线，而是 `Skill_Player.HitTargetEvent`、`ICharacter.OnAttackEvent/HurtEvent/DieEvent/UpdateEvent` 等 C# event，以及 Brain 内的共享数据事件。
- **资源/对象池**：特效走 `PoolSystem.GetGameObject` / `GameObjectPushPool`，取不到池对象时 `Instantiate` 兜底；`ResSystem.GetOrNew<SkillShareData<T>>` 用于共享数据；`EffectController` 自己在 `Update` 里计时回池。
- **相机**：硬依赖 Cinemachine（`CinemachineVirtualCameraBase`、`CinemachineImpulseSource/ImpulseListener`、`CinemachineVirtualCamera/FreeLook` 的 Lens）；`SkillCamera` 用 `[DefaultExecutionOrder(-100)]` 抢在普通脚本前。
- **时间系统**：`ITimeOwner.timeScaleContainer` 取 delta；顿帧走 `TimeSystem.SetShutter/ReceiveShutter`，由 TimeSystem 统一管理协程覆写。
- **状态机**：`ICharacter : IStateMachineOwner`，技能结束靠 `Exiting` + 动画过渡完成回到普通状态（具体实现在 Demo 层 Brain）。

## 设计亮点与可改进点

**亮点**：数据/逻辑/表现三层分离，Clip 是纯数据、Behaviour 是逻辑、Processor 是表现；Tick 顺序固定，帧事件生效次序可预测；Before/After 钩子 + `out` 参数让行为可在不改数据的前提下改写播放；处理器用泛型类型键注册，未注册即静默跳过，天然支持「按角色裁剪表现」；帧→秒换算集中在 `CreateCameraEventTime` 一处；`OnDetection` 的 `CheckData` 用「周期清空 HashSet」优雅实现多段连击命中。

**可改进点**：

> **状态更新**：本清单是首次通读时的记录。其中第 1、2、4、5 条（特效实例串位、检测循环里的 `return`、`ReleaseAgain` 索引缺 key、兜底实例被塞回池）**已在后续版本修复**，保留在此仅作为问题记录。第 3、6、7 条是设计观察与待确认项。

1. `TickSkillEffectEvent` 用单个 `_currentEffect` 字段，且 `else` 分支会把该特效位移到**其它**特效事件的 `Position`——同屏多个特效必然位置错乱，应按事件分别持有实例。
2. `TickSkillAttackDetectionEvent` 的形状检测循环中 `return` 写在 `List.ForEach` 的 lambda 内，一旦某个 `hitTarget` 为空或 `OnDetection` 返回 false，本帧剩余碰撞体与 `AfterAttackDetectionEvent` 都被跳过，应改 `continue`。
3. `SkillFrameEventBase` 是个空基类，全工程只有 `SkillAnimationEvent` 继承它，音频/特效/自定义/检测/相机事件各自独立，缺少统一帧事件抽象；新增轨道必须同时改 `SkillClip` 与 `Skill_Player`，扩展成本高于处理器体系。
4. `SkillBrainBase.ReleaseAgain` 直接 `SkillBehaviourDic[LastUsedSkillConfig]` 索引，缺 key 会抛异常；`Skill_Player` 的 `AttackDetectionType` 是 public 可变字段，被每个检测事件覆写并被 Gizmos 读取，属隐式全局状态。
